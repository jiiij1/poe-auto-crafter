# POE 自动制作工具

一款基于 Python/Tkinter 的 Path of Exile (POE) 装备自动制作工具。支持**规则模式**（单规则循环）和**流程模式**（可视化流程图编排），通过读取游戏内复制的装备文本进行词条匹配，自动执行鼠标/键盘动作。

## 功能概述

| 功能 | 说明 |
|------|------|
| 剪贴板读取 | 向游戏发送复制快捷键，读取装备文本 |
| 蓝色词条匹配 | 至少匹配 X 条（可配置） |
| 红色词条匹配 | 必须全部包含 |
| 多套规则 | 支持创建、保存、切换、导入、导出多套规则 |
| 自定义动作 | 支持 moveTo、click、sleep、hotkey、press、keyDown、keyUp |
| 简化脚本 | 动作可用简化文本编辑，自动转译为 JSON |
| 规则模式 | 单规则 + 单动作 + 失败重试的简单循环 |
| 流程模式 | 可视化流程图，多节点通过成功/失败/次数耗尽分支自由组合 |
| 循环保护 | 每个节点独立设置最大动作次数，防止无限循环 |
| 实时高亮 | 流程运行时高亮当前执行节点 |
| F9 取点 | 按 F9 读取鼠标坐标到输入框 |
| F10 启停 | 全局开始/停止热键 |

### 运行控制

位于规则模式顶部：

| 控件 | 说明 |
|------|------|
| 状态标签 | 显示"运行中"（绿色）或"停止"（红色） |

### 匹配规则配置

#### 蓝色词条

蓝色词条采用**至少匹配 X 条**的规则。

例如填写 3 条蓝色词条：

```
火焰伤害
闪电伤害
冰霜伤害
```

设置"至少匹配 X 条蓝色词条"为 `2`，则剪贴板中包含其中任意 2 条即算满足。

#### 红色词条

红色词条采用**必须全部包含**的规则。

例如填写：

```
生命
抗性
```

则剪贴板中必须同时包含"生命"和"抗性"，否则匹配失败。

#### 最大尝试次数

仅用于规则模式。当连续尝试达到此次数仍未匹配成功时，自动停止。

### 动作配置

动作是鼠标/键盘操作的序列，例如"改造"动作：

```
moveTo 110,270
click right
sleep 0.034
moveTo 330,440
click left
sleep 0.1
```

| 控件 | 说明 |
|------|------|
| 选择动作 | 下拉框切换已保存的动作 |
| 动作名 | 显示/修改当前动作名称 |
| 保存 | 保存当前动作（修改名称后自动新建） |
| 删除 | 删除当前选中的动作 |
| 重载配置 | 从磁盘重新读取 actions_config.json |

> **注意**：没有"新建"按钮。修改动作名称后点击"保存"即可创建新动作。

### 鼠标取点

| 控件 | 说明 |
|------|------|
| X / Y 输入框 | 显示鼠标坐标 |
| 读取鼠标位置 (F9) | 按 F9 或点击按钮读取当前鼠标坐标 |
| 插入 moveTo | 在动作脚本中插入 `moveTo x,y` |
| 插入 moveTo + 右键 | 插入 `moveTo` + `click right` + `sleep 0.05` |
| 插入 moveTo + 左键 | 插入 `moveTo` + `click left` + `sleep 0.05` |

**操作流程**：

1. 将鼠标移动到目标位置（如改造石）
2. 按 F9 读取坐标
3. 点击"插入 moveTo + 右键"
4. 根据需要修改 sleep 时间
5. 重复上述步骤插入下一个动作
6. 点击"保存"

### 流程编辑器画布

画布是流程图的核心编辑区域，位于右侧。

**画布上的元素**：

```
┌────────────────────────┐
│ ▶ 节点1                 │  ← 绿色背景 = 开始节点
├────────────────────────┤
│ 动作: 改造              │
│ 规则: 检查混沌抗性       │
├────────────────────────┤
│ ● 成功    ● 失败    ● 耗尽 │  ← 三个输出端口
└────────────────────────┘
```

**节点颜色**：

| 颜色 | 含义 |
|------|------|
| 绿色背景 | 开始节点 |
| 蓝色背景 | 普通动作节点 |
| 红色背景 | 结束节点 |
| 蓝色边框 | 当前选中的节点 |
| 橙色边框 | 运行时当前正在执行的节点 |

**端口颜色**：

| 颜色 | 端口 | 说明 |
|------|------|------|
| 绿色 | 成功 | 匹配成功时走此分支 |
| 红色 | 失败 | 匹配失败时走此分支 |
| 橙色 | 耗尽 | 该节点执行次数达到上限时走此分支 |
| 蓝色 | 输入 | 节点左侧，接收其他节点的连接 |

**连接线**：

- 绿色连接线 = 成功分支
- 红色连接线 = 失败分支
- 橙色连接线 = 次数耗尽分支
- 连接线上方标注分支名称

### 节点编辑对话框

**双击节点**或**右键 → 编辑节点**打开：

```
┌──────────────────────────────────────┐
│ 编辑节点 - 节点1                      │
├──────────────────────────────────────┤
│ 节点名称:    [第一次改造            ] │
│ 动作:        [改造               ▼] │
│ 匹配规则:    [检查混沌抗性         ▼] │
│ 成功 →       [node_2              ▼] │
│ 失败 →       [self                ▼] │
│ 最大动作次数: [9999                 ] │
│ 次数耗尽 →   [end                  ▼] │
├──────────────────────────────────────┤
│        [ 确定 ]    [ 取消 ]          │
└──────────────────────────────────────┘
```

**字段说明**：

| 字段 | 说明 |
|------|------|
| 节点名称 | 显示在节点上的名称 |
| 动作 | 下拉选择已创建的动作（来自 actions_config.json） |
| 匹配规则 | 下拉选择已创建的规则（来自 rules_config.json） |
| 成功 → | 匹配成功后跳转到哪个节点，可选任意已有节点或 `end` |
| 失败 → | 匹配失败后跳转到哪个节点，可选任意已有节点、`self`（重新执行本节点）或 `end` |
| 最大动作次数 | 该节点最多执行多少次（默认 9999），达到上限走"次数耗尽"分支 |
| 次数耗尽 → | 达到最大次数后跳转到哪个节点，可选任意已有节点、`self` 或 `end` |

> **循环示例**：将"失败 →"设为 `self`，该节点会反复执行直到匹配成功或达到最大次数。

### 连接线操作

#### 方式一：从端口拖拽

1. 鼠标左键按住节点右侧的端口（绿色/红色/橙色圆点）
2. 拖拽到目标节点上
3. 松开鼠标，连接建立

#### 方式二：右键菜单

1. 右键点击源节点
2. 选择"从成功端口连接"、"从失败端口连接"或"从次数耗尽端口连接"
3. 左键点击目标节点完成连接

### 右键菜单详解

在画布上**右键点击节点**弹出菜单：

```
┌─────────────────────────┐
│ 编辑节点                 │  ← 打开节点编辑对话框
│ 复制节点                 │  ← 复制该节点（连接清空）
│ 删除节点                 │  ← 删除该节点及其所有连接
├─────────────────────────┤
│ 设为开始节点             │  ← 将该节点设为流程起点
├─────────────────────────┤
│ 从成功端口连接           │  ← 进入连接模式，左键点击目标完成连接
│ 从失败端口连接           │  ← 同上，从失败端口出发
│ 从次数耗尽端口连接       │  ← 同上，从次数耗尽端口出发
└─────────────────────────┘
```

在画布**空白区域右键**：菜单项全部禁用。

### 流程验证

点击"验证流程"按钮，程序会检查以下项目：

| 检查项 | 说明 |
|--------|------|
| 开始节点是否存在 | 必须设置一个开始节点 |
| 开始节点是否有效 | 开始节点必须存在于节点列表中 |
| 动作引用是否有效 | 节点引用的动作必须存在于 actions_config.json |
| 规则引用是否有效 | 节点引用的规则必须存在于 rules_config.json |
| 成功分支目标是否有效 | 成功分支指向的节点必须存在 |
| 失败分支目标是否有效 | 失败分支指向的节点必须存在 |
| 次数耗尽分支目标是否有效 | 次数耗尽分支指向的节点必须存在 |
| 是否有无出口的节点 | 普通节点至少要有一个出口分支 |
| 是否有结束节点 | 流程中必须有结束节点或指向 end 的分支 |
| 是否有不可达节点 | 所有节点必须能从开始节点到达 |

验证失败时会显示具体错误：

```
流程验证失败：

节点「继续制作」
失败分支没有连接。

节点「检查抗性」
引用的规则「鞋子规则2」不存在。
```

### 流程运行

1. 点击左侧"运行流程 (F10)"按钮或按 F10
2. 程序自动保存并验证流程
3. 从开始节点依次执行：
   - 执行节点的动作
   - 等待游戏稳定
   - 读取装备剪贴板
   - 使用节点的规则匹配
   - 根据结果跳转到成功/失败/次数耗尽分支
4. 到达结束节点或按 F10 停止

**运行日志示例**：

```
流程开始运行...
执行节点: 第一次改造 (第 1/9999 次)
  执行动作: 改造
  匹配失败: 蓝色 0/1，红色缺失=['混沌抗性']
执行节点: 第一次改造 (第 2/9999 次)
  执行动作: 改造
  匹配成功: 蓝色 1/1
执行节点: 继续制作 (第 1/9999 次)
  执行动作: 富化
  匹配成功: 蓝色 2/2
流程正常结束
```

**循环保护**：每个节点有独立的最大动作次数（默认 9999）。当某个节点执行次数达到上限时，自动走"次数耗尽"分支（默认结束）。

### 流程配置文件格式

流程保存在 `workflows_config.json`：

```json
{
  "__selected_workflow__": "鞋子制作",
  "workflows": {
    "鞋子制作": {
      "start_node": "node_1",
      "nodes": {
        "node_1": {
          "name": "第一次改造",
          "action": "改造",
          "rule": "检查混沌抗性",
          "success": "node_2",
          "failure": "node_1",
          "max_attempts": 9999,
          "max_reached": "end",
          "x": 100,
          "y": 100
        },
        "node_2": {
          "name": "继续制作",
          "action": "富化",
          "rule": "检查生命",
          "success": "end",
          "failure": "node_1",
          "max_attempts": 9999,
          "max_reached": "end",
          "x": 400,
          "y": 100
        },
        "node_3": {
          "type": "end",
          "name": "结束",
          "x": 700,
          "y": 100
        }
      }
    }
  }
}
```

**字段说明**：

| 字段 | 说明 |
|------|------|
| `start_node` | 开始节点的 ID |
| `nodes` | 所有节点的字典，key 为节点 ID |
| `name` | 节点显示名称 |
| `action` | 引用的动作名称（来自 actions_config.json） |
| `rule` | 引用的规则名称（来自 rules_config.json） |
| `success` | 匹配成功后跳转的节点 ID，`"end"` 表示结束 |
| `failure` | 匹配失败后跳转的节点 ID，`"self"` 表示重新执行本节点 |
| `max_attempts` | 该节点最大执行次数 |
| `max_reached` | 达到最大次数后跳转的节点 ID |
| `x`, `y` | 节点在画布上的位置坐标 |
| `type` | `"end"` 表示结束节点 |

## 常见问题

### 1. 按 F10 没有反应

- 检查是否安装了 `keyboard`：`pip install keyboard`
- 以管理员身份运行程序
- 检查热键是否被其他软件占用
- 修改 `actions_config.json` 中的 `hotkey` 为其他按键

### 2. 剪贴板读取失败

- 确认游戏窗口有焦点
- 确认复制快捷键与游戏内一致
- 检查是否安装了 `pyperclip`

### 3. 动作点击位置不准

- 固定游戏分辨率和窗口位置
- 重新按 F9 取点
- 不要移动游戏窗口

### 4. 流程运行时节点不跳转

- 检查节点的"成功"/"失败"/"次数耗尽"分支是否已连接
- 点击"验证流程"检查是否有错误
- 查看流程日志确认匹配结果

### 5. 程序误操作

- 初次使用先勾选"试运行"
- 确保随时能按 F10 停止
- 不要在重要操作时使用未测试的动作
